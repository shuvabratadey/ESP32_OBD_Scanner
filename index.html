A custom OBD2 diagnostic device built with an ESP32 and TJA1050 CAN transceiver, serving a real-time live dashboard over Wi-Fi and BLE — including a companion Android app. This documents the full journey from learning CAN Bus to a working product.

01 The Journey

This project started with curiosity about how CAN Bus works in motorcycles and cars, and ended with a fully custom OBD2 scanner with a web server and Android app. Here's how it unfolded:

Phase 1 — Learning: ELM327 + Serial Debug
Purchased an ELM327 Mini Bluetooth adapter and connected it to Windows via Serial Debug Assistant. Sent raw AT commands and OBD2 PIDs manually to understand exactly how the protocol works — what bytes are sent, what bytes come back, how to decode RPM, speed, temperature, and DTCs. Wrote full documentation of everything learned.
Phase 2 — Hardware Design: ESP32 + TJA1050
Chose the ESP32 for its built-in Wi-Fi and BLE, and the TJA1050 CAN transceiver to interface directly with the vehicle CAN Bus (OBD2 pins 6 and 14). Designed and assembled the circuit, wiring CAN TX/RX to GPIO 5/4.
Phase 3 — Firmware: Wi-Fi Version
Wrote the first firmware — an ESP32 acting as a Wi-Fi Access Point with a built-in web server. The dashboard is a single-page HTML app served from PROGMEM with real-time JSON polling, live gauges, DTC read/clear, CSV recording, and VIN reading via ISO-TP multi-frame.
Phase 4 — Firmware: BLE Version + Android App
Wrote a second firmware where the ESP32 exposes each OBD2 parameter as a BLE characteristic with NOTIFY support. Built a companion Android app that subscribes to BLE notifications and displays live gauges. The app also allows reading VIN, DTC codes, and clearing faults.

02 How It Works

The ESP32 directly reads vehicle sensor data by speaking OBD2 over CAN Bus — no ELM327 chip in between. The TJA1050 handles the physical CAN layer.

[Vehicle ECU] │ │ CAN Bus (OBD2 Pin 6 = CAN-H, Pin 14 = CAN-L) │ 500 kbps, ISO 15765-4 (11-bit IDs) │ ▼ [TJA1050 Transceiver] │ RX → GPIO 4 TX ← GPIO 5 │ ▼ [ESP32] │ Sends request frame to 0x7DF │ Waits for response from 0x7E8 │ Decodes bytes using OBD2 formulas │ Updates value cache every 500ms │ ├──▶ [Wi-Fi AP] ──▶ Browser on phone/laptop │ └─ JSON API /api/data every 1s │ └─ HTML dashboard from PROGMEM │ └─ CSV recording to SPIFFS │ └──▶ [BLE Server] ──▶ Android App └─ NOTIFY characteristics per parameter └─ READ-ONLY characteristics for VIN, DTC, ECU

OBD2 Request / Response Flow

// ESP32 sends request to broadcast address 0x7DF
TX CAN Frame (ID=0x7DF):
  [02] [01] [0C] [00] [00] [00] [00] [00]
   │     │     └── PID = 0x0C (Engine RPM)
   │     └──────── Mode = 0x01 (current data)
   └────────────── 2 bytes of payload follow

// Vehicle ECU responds from 0x7E8
RX CAN Frame (ID=0x7E8):
  [04] [41] [0C] [1A] [F8] [00] [00] [00]
   │     │     │     └──┴── Data bytes A=0x1A, B=0xF8
   │     │     └──────────── PID echoed back
   │     └────────────────── 0x40 + mode = positive response
   └──────────────────────── 4 data bytes follow

// Decode: RPM = (256 * 0x1A + 0xF8) / 4 = 1726 RPM

03 Circuit Connection Diagram

The TJA1050 CAN transceiver converts ESP32's 3.3V TTL logic CAN signals to the differential CAN Bus levels required by ISO 11898 / ISO 15765-4.

Note on TJA1050 supply: The TJA1050 VCC requires 5V. Use the ESP32 DevKit's 5V pin (powered via USB) or a dedicated 5V regulator from the 12V OBD2 supply. The TX/RX signals are 3.3V-compatible on the TJA1050 inputs.

How to Connect (Wi-Fi Mode)

1

Plug in the scanner

Connect the ESP32 scanner to the vehicle OBD2 port. Power LEDs will blink 5 times on startup.

2

Connect to Wi-Fi

On your phone or laptop, connect to OBD2-Bike (password: 12345678).

3

Open the browser

Navigate to http://192.168.4.1 or http://obd.local — a captive portal will redirect you automatically.

4

Select parameters

Go to the Settings tab, choose which parameters to monitor, and tap Save. Your selection persists in EEPROM across power cycles.

5

View live data

The DASH tab shows live gauges. Values update every second. "ERR" means that PID didn't respond (not supported by your vehicle's ECU).
